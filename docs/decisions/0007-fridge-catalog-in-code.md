# 0007 – קטלוג דגמי מקררים כקובץ בקוד

## הקשר
המשתמש רוצה לבחור יצרן ודגם ולקבל מקרר מוכן. חקרנו את אתרי לנדרס ווינופו (73 דגמים): מפורסמים הקיבולת, המידות ולפעמים מספר המדפים, אבל **לא** כמה בקבוקים בכל מדף.

## החלטה
- הקטלוג הוא קובץ TypeScript (`src/lib/fridge-catalog.ts`): לכל דגם רק העובדות שפורסמו וקישור למקור.
- הפונקציה הטהורה `estimateShelves()` הופכת את העובדות לסידור התחלתי שמסתכם **בדיוק** בקיבולת שפורסמה. הכללים כויילו על תמונות מוצר (מדף של 5+ בקבוקים = שתי שורות מדורגות, n ו־n−1; אזור תחתון של כ־15%).
- בטופס כתוב במפורש שזו הערכה, עם קישור לעמוד הדגם. הכול ניתן לשינוי.
- דגמים זהים בגוף (אותן מידות בדיוק, למשל LA75B ו־SU-75B) משתמשים במספר המדפים שפורסם לאחד מהם.

## חלופות שנדחו
- **טבלת `fridge_models` במסד**: צריך migration לכל תיקון בנתונים, ואין עדיין מי שעורך אותה מהממשק. הטבלה נשארת לשלב שבו משתמשים יוכלו לשתף סידור מדויק שמדדו.
- **להמציא סידור "אמיתי"**: מטעה. עדיף הערכה שאומרת שהיא הערכה.
- **רק דגמים עם נתונים מלאים**: כמעט אין כאלה.

## השלכות
- בדיקת Vitest מוודאת שכל דגם מסתכם בקיבולת שלו ונכנס במגבלות של `create_fridge`.
- עדכון הקטלוג = שינוי קוד ו־PR, עם היסטוריה בגיט.
